# ADR-0018: デザインシステムの主用途をスライド（配布・投影）に置き、フォントとコード配色を改める

- **ステータス**: `承認済み`
- **決定日**: 2026-09-13
- **決定者**: masaya_ueki
- **関連タスク**: #159
- **関連 ADR**: [ADR-0016](./0016-claude-design-design-system-file.md)（デザインシステムを `docs/design/` に置く判断）／ ADR-0017（指示書形式の改訂。#158 で並行して追加）

---

## コンテキスト

[ADR-0016](./0016-claude-design-design-system-file.md) で、Claude Design に読み込ませるデザインシステムを [design-system-notion-like.md](../design/design-system-notion-like.md) の 1 ファイルにした。#152 のハンズオン資料をこのデザインシステムで作り、PowerPoint で配布・投影したところ、次の問題が見つかった。

1. **スライドの定義が足りない** — 内容の中心が Web / UI（ボタン・入力欄・サイドバー・レスポンシブ）で、スライドは付録の表 1 つだけだった。
2. **ハンズオンで使う部品が無い** — コードブロック・TIPS / 注意・手順番号・画面キャプチャが未定義で、Claude Design が定義外の配色とフォントを独自に作った。
3. **フォントが置き換わる** — Inter / Noto Sans JP は Windows に標準で入っておらず、PowerPoint では Yu Gothic UI / Meiryo / BIZ UDゴシック などが混在した。
4. **本文の下限が守られない** — 本文は 18〜20px、コードは 14〜15px 程度まで下がっていた。
5. **ページ数が膨らむ** — 「入りきらないときは縮小ではなく分割する」ルールにより、ページ数の上限がある資料でもページが増え続けた。

崩れの原因は世界観や配色ではなく定義の不足にあるため、Notion ライクの世界観・配色（有彩色は accent 1 色）・図表 3 色ルールは維持する。

## 決定事項

1. **主用途をスライド（配布・投影 / PowerPoint）に置き、本文をスライド前提に組み替える。** Web / UI 向けの記述は付録に移す。`DESIGN.md` 形式の 9 セクション構成は保ち、8 章は Responsive から Output & Delivery（配布・投影）に替える。
2. **フォントを Yu Gothic UI（基本）＋ BIZ UDゴシック（コード）にする。** どちらも Windows 標準搭載で、PowerPoint で置き換わらない。本文の下限は 20px、コードの下限は 18px。
3. **コードブロックのエディタ風配色（4 色）を図表 3 色ルールの例外にする。**
4. **ページ数の上限があるときは分割せず、優先度の低い情報から削る。**

## 検討した選択肢

### フォント

#### 選択肢A: Yu Gothic UI ＋ BIZ UDゴシック（採用）

- **メリット**: Windows 10 以降に標準搭載で、配布先の PowerPoint でも置き換わらない。参考資料でも大半が Yu Gothic UI で、コードは BIZ UDゴシック だった。BIZ UDゴシック は等幅で、UD（ユニバーサルデザイン）書体のため投影でも読みやすい。
- **デメリット**: Mac では標準搭載でない場合がある。Yu Gothic UI に weight 500 が無い。

#### 選択肢B: Inter ＋ Noto Sans JP を維持し、フォントを埋め込む（不採用）

- **メリット**: Web との見た目が揃う。デザインシステムの変更が最小で済む。
- **デメリット**: 埋め込みはファイルが重くなり、編集側の環境によっては無効になる。
- **不採用理由**: 配布先の PowerPoint で再現されない実例があった。Claude Design の書き出しで埋め込みを制御できない。

#### 選択肢C: Meiryo（メイリオ）（不採用）

- **メリット**: Windows 標準搭載で、古い環境にも入っている。
- **デメリット**: 字面が大きく行間が広いため、1920×1080 の本文 20px では 1 ページに入る量が減る。等幅書体を別に選ぶ必要がある。
- **不採用理由**: Yu Gothic UI のほうが Notion ライクの静かな文書型の見た目に近く、参考資料でも主に使われていた。

### コードの配色

#### 選択肢A: エディタ風のダーク配色を図表 3 色ルールの例外にする（採用）

- **メリット**: 色で構文（コメント・文字列・キー）を識別でき、読みやすい。参考資料のコードブロックが好評だった。
- **デメリット**: 有彩色が accent 以外に増える。例外が広がると色が無秩序に増える恐れがある。
- **対策**: 使える色を参考資料の 4 色（背景 `#131C1A` / 基本の文字 `#D4DED9` / コメント `#8AA098` / 文字列・キー `#CBB582`）に固定し、コードブロックの外では使わない。

#### 選択肢B: 図表 3 色（accent / text-muted / border）で塗る（不採用）

- **メリット**: 例外を作らずに済む。
- **デメリット**: 3 色では構文を識別できず、読みにくい。
- **不採用理由**: コードは色で構文を識別すること自体に意味があり、3 色ルールの趣旨（見栄えのための色を増やさない）に当たらない。

### 情報が入りきらないとき

#### 選択肢A: 優先度の低い情報から削る（採用）

- **メリット**: ページ数の上限を守れる。1 ページ 1 メッセージが保たれる。
- **デメリット**: 何を削るかの判断が要る。

#### 選択肢B: ページを分割する（不採用）

- **メリット**: 情報を落とさない。
- **デメリット**: ページ数が膨らみ、上限のある資料（ハンズオンの時間枠など）に収まらない。
- **不採用理由**: 参考資料でページ数が膨らむ原因になった。

## 結果・トレードオフ

- デザインシステムの本文がスライド前提になり、コードブロック・TIPS / 注意の枠・手順番号・画面キャプチャの枠を定義した。部品を足すときも既存トークン・スペーシングスケール・角丸 4/8px の範囲で作る。
- **定義外の色を作らない。** 参考資料で使われていた定義外の色（警告・強調用の赤紫や紫など）は採用しない。例外はコードブロックの 4 色だけ。
- Mac では Yu Gothic UI / BIZ UDゴシック が標準搭載でない場合があり、フォールバックに置き換わる。仕上がりは Windows の PowerPoint で確認する。
- ページ数の上限がある資料では情報が落ちる。削る対象は優先度で決め、文字を小さくして収めない。
- Claude Design 側のデザインシステムは自動では変わらない。差し替えは手動（[docs/design/README.md](../design/README.md) の手順 A）で行う。
- **見直し条件**: (1) 配布・投影の基準が Windows の PowerPoint でなくなったとき、(2) Claude Design がフォント埋め込みを制御できるようになったとき、(3) コードブロックの 4 色で構文を識別しきれない事例が続いたとき。
