# Notion ライク デザインシステム（Claude Design 用）

> **これは何か**: Claude Design（claude.ai/design）に読み込ませる**デザインシステム定義ファイル**。
> **主な用途はスライド（配布・投影 / PowerPoint 書き出し）**。本文（1〜9 章）はスライドを前提に書き、Web / UI モックで使う値は末尾の「付録: Web / UI への適用」にまとめる。
> **見た目はこのファイルだけで決める。ここに無い色・フォント・部品を作らない。**
> **使い方・運用**: [docs/design/README.md](./README.md) ／ **採用理由**: [ADR-0016](../adr/0016-claude-design-design-system-file.md) ／ **スライド中心・フォント・コード配色の根拠**: [ADR-0018](../adr/0018-design-system-slide-first-windows-fonts.md)

コミュニティで定着している `DESIGN.md` 形式（9 セクション構成）に従う。
Claude Design はこのファイル 1 枚を読めば、未定義のケースに出会っても「なぜそうするのか」から判断できる。

## 1. Visual Theme & Atmosphere（世界観）

**コンセプト**: Notion ライク。**余白と罫線だけで構造を示す**、静かな文書型の資料。

| 軸 | 立ち位置 |
|---|---|
| 密度 | 低〜中。詰め込まず、優先度の低い情報から削る |
| 彩度 | 極小。色は「意味」が必要なときだけ使う |
| 装飾 | なし。影・グラデーション・立体・イラストを使わない |
| 温度 | ややウォームなニュートラル（純黒 `#000` / 純グレー `#808080` は使わない） |
| 声のトーン | 事実ベース・断定的・短い。煽らない |

**なぜ**: 情報そのものを主役にするため。装飾で差をつけるのではなく、**余白のリズムと階層の一貫性**で読みやすさを作る。判断に迷ったら「引く」方を選ぶ。

**背景は必ずウォームホワイト `#FFFFFF`、文字はウォームブラック `#37352F`。** この 2 色が世界観の土台で、ここを崩すと Notion らしさは失われる（暗い面はコードブロックの中だけ）。

## 2. Color Palette & Roles（配色と役割）

```css
:root {
  /* Text */
  --text:            #37352F;  /* 本文・見出し（ほぼ黒／ウォーム） */
  --text-muted:      #787774;  /* 補足・キャプション・出典・フッター */
  --text-disabled:   #9B9A97;  /* 非活性（Web） */
  --text-on-accent:  #FFFFFF;

  /* Surface */
  --bg:              #FFFFFF;  /* 基本背景 */
  --bg-subtle:       #F7F6F3;  /* カード・ゾーニング・表ヘッダー */
  --bg-hover:        #F1F1EF;  /* ホバー・選択行（Web） */

  /* Line */
  --border:          #E9E9E7;  /* 罫線・区切り（常に 1px） */
  --border-strong:   #D3D1CB;  /* 強い罫線（Web の入力欄など） */

  /* Accent（唯一の有彩色） */
  --accent:          #2383E2;
  --accent-hover:    #0B6BCB;  /* ホバー（Web） */
  --accent-soft:     #DDEBF7;  /* 面塗り・強調行 */

  /* Semantic（状態表示のみ。装飾に使わない） */
  --success:         #448361;
  --warning:         #CB912F;
  --danger:          #D44C47;
  --success-soft:    #EDF3EC;
  --warning-soft:    #FBF3DB;
  --danger-soft:     #FDEBEC;
}
```

### 役割ルール

| ルール | 内容 |
|---|---|
| **有彩色は accent 1 色** | 1 ページに accent を使う箇所は **1〜2 か所まで**。それ以上は「どれも目立たない」と同義 |
| **semantic は状態専用** | success / warning / danger は**状態を表すときだけ**（「注意」の枠を含む）。強調・装飾・グラフの系列色に流用しない |
| **文字色は 3 種** | `--text` / `--text-muted` / `--accent`。それ以外の色で文字を塗らない（コードブロックの中だけは下記のコード配色） |
| **色に意味を委ねない** | 「赤＝悪 / 緑＝良」だけで伝えない。必ず語・記号・順序を併記する（色覚多様性・白黒印刷対策） |

### 図表 3 色ルール（最重要）

**グラフ・表・図で使える色は次の 3 色だけ。** この 3 色をまとめて **`chart_palette`** と呼ぶ。

値は 2 章のトークンを参照する（hex を書き写さない。§2 を直せば図表にも伝わる）。

```css
:root {
  --chart-1: var(--accent);
  --chart-2: var(--text-muted);
  --chart-3: var(--border);
}
```

| # | トークン | 実体 | 役割 |
|---|---|---|---|
| 1 | `--chart-1` | `--accent` | 注目させたい系列・推奨案・現在地 |
| 2 | `--chart-2` | `--text-muted` | 比較対象・その他 |
| 3 | `--chart-3` | `--border` | 母数・背景・非注目 |

**例外**: 構成説明図・状態遷移図など、**色が意味の識別そのものを担う**場合に限り 4 色目以降を許可する。その場合も彩度を抑えたトーンで統一し、図の中に凡例を置く。**「見栄えのため」は例外理由にならない。** コードブロックは下記の専用配色を使う。

### コードブロック配色（図表 3 色ルールの例外）

> **設計根拠**: [ADR-0018](../adr/0018-design-system-slide-first-windows-fonts.md)

コードは読みやすさを優先し、**エディタ風のダーク配色**を使う。色で構文を識別すること自体に意味があるため、図表 3 色ルールの対象外とする。

```css
:root {
  --code-bg:      #131C1A;  /* 背景 */
  --code-text:    #D4DED9;  /* 基本の文字（キーワード・関数名・数値・記号を含む） */
  --code-comment: #8AA098;  /* コメント */
  --code-string:  #CBB582;  /* 文字列・キー（JSON / YAML / frontmatter のキー） */
}
```

**使えるのはこの 4 色だけ。** キーワード・関数名・数値などに別の色を作らない（すべて `--code-text`）。この 4 色をコードブロックの外（本文・図表・装飾）で使わない。

## 3. Typography Rules（タイポグラフィ）

> **設計根拠**: [ADR-0018](../adr/0018-design-system-slide-first-windows-fonts.md)

```css
--font-sans: "Yu Gothic UI", "Yu Gothic", "Meiryo", sans-serif;
--font-mono: "BIZ UDゴシック", "BIZ UDGothic", "MS Gothic", monospace;
```

基本は **Yu Gothic UI**、コードは等幅の **BIZ UDゴシック**。どちらも Windows に標準搭載（Yu Gothic UI は 8.1 以降、BIZ UDゴシックは Windows 10 1809 以降）で、PowerPoint で置き換わらない。
**欧文用フォントを別に指定しない。** 両書体とも和文と揃う欧文字形を持つため、1 書体で和欧混植を賄う（欧文だけ別書体にすると、配布先に無い書体が置き換わる原因になる）。

### スケール（スライド 1920×1080px）

pt は PowerPoint 上の値（`pt = px × 0.75`）。

| 用途 | size | pt | weight | line-height | color |
|---|---|---|---|---|---|
| ページタイトル | 40px | 30pt | 700 | 1.3 | `--text` |
| キーメッセージ | 28px | 21pt | 600 | 1.5 | `--text` |
| 本文（下限） | 20px | 15pt | 400 | 1.7 | `--text` |
| コード（下限） | 18px | 13.5pt | 400 | 1.5 | コードブロック配色（§2） |
| ラベル | 16px | 12pt | 600 | 1.4 / letter-spacing 0.04em | `--text` または `--text-muted` |
| 脚注・出典・フッター | 14px | 10.5pt | 400 | 1.4 | `--text-muted` |

### ルール

- **本文 20px・コード 18px は配布・投影用の下限。** これより小さくしてよいのはラベル・脚注・出典・フッターだけ
- weight は **400 / 600 / 700 の 3 段だけ**（Yu Gothic UI に 500 は無い）
- **太字は 1 ページ 3 か所まで。** 下線・斜体・影文字・全角スペースでの字下げは使わない
- 見出しは階層を飛ばさない
- 本文 1 文は **40 字以内**。超えたら文を割る
- 数字・英字は半角。単位は数値と半角スペースで区切る（`1,240 件`）
- 本文サイズを下げて情報を詰めない。入らないときの扱いは §9 原則 4 に従う

## 4. Component Stylings（コンポーネント）

すべて **枠線 1px＋弱い面色** で構成し、影は使わない（→ 6 章）。
新しい部品が要るときも、**既存トークン・スペーシングスケール・角丸 4/8px の範囲だけ**で作る（色の例外はコードブロックの 4 色のみ）。

### Card

`bg --bg-subtle` / `radius 8px` / `padding 24px` / **枠線なし・影なし**
背景の上に置く場合のみ `1px solid --border` を許可（面色と枠線は併用しない）。

### Table

- **横罫線のみ。縦罫線は引かない**（`border-bottom 1px solid --border`）
- ヘッダー行: `bg --bg-subtle` ＋ ラベル スタイル
- セル: `padding 12px 16px` / 数値は右揃え・等幅 / 文字は左揃え
- 強調行は `--accent-soft`（1 行まで）
- **表の下には必ず結論を 1 行置く**（表は主張ではなく根拠）

### Callout（キーメッセージの帯）

左に `4px` の `--accent` バー ＋ 背景 `--bg-subtle` / `padding 16px 20px` / `radius 0 4px 4px 0`。文字はキーメッセージ スタイル。
**1 ページに 1 つまで。** semantic を使う場合はバーと背景をペアで替える（`--danger` ＋ `--danger-soft` 等）。

### TIPS / 注意の枠

ハンズオンの補足（TIPS）とつまずきポイント（注意）を示す帯。

| 種類 | バー | 背景 | ラベル語 |
|---|---|---|---|
| TIPS | 左 4px `--text-muted` | `--bg-subtle` | 「TIPS」 |
| 注意 | 左 4px `--warning` | `--warning-soft` | 「注意」 |

共通: `padding 16px 24px` / `radius 0 4px 4px 0` / 先頭にラベル語（ラベル スタイル・`--text`）、続けて本文スタイルで 1〜2 行。

- **ラベル語を必ず書く。** 色だけで TIPS と注意を区別しない
- **TIPS と注意は合わせて 1 ページに 1 つまで**
- **キーメッセージの帯と同じページに帯で置かない。** 並べたいときは帯にせず、脚注の位置にラベル語＋1 行（本文スタイル・`--text-muted`）で置く

### 手順番号

- 表記は `STEP 1` / `STEP 2`（ラベル スタイル・`--text-muted`）。下に手順名（本文サイズ・600）と説明（本文）を置く
- 並べ方は縦（上から下）が基本。横に並べるのは 4 手順まで、間隔 32px
- 番号は accent で塗らない。現在地を示すときだけ、該当する 1 つを `--accent` にする
- 丸数字（①）・塗りの円・矢印の装飾は使わない

### 画面キャプチャの枠

- `1px solid --border` / `radius 4px` / 影なし。縦横比を保つ（引き伸ばさない）
- 注目箇所は `2px --accent` の矩形（`radius 4px`）で囲む。1 枚に 1 か所まで
- 画像の下にキャプション（脚注スタイル）で「何の画面か」を書く
- 小さくすると読めない場合は、縮小せず必要な部分だけを切り抜く
- 個人情報・社外秘は `--bg-subtle` で塗りつぶす

### コードブロック

- 背景 `--code-bg` / `radius 8px` / `padding 24px` / 枠線なし
- 書体 `--font-mono`、コード スタイル（18px 以上）
- 色分けは §2 のコードブロック配色の 4 色だけ。行の強調に背景色・下線を足さず、コメント（`# ← ...`）で示す
- ファイル名・見出しはブロックの外、上にラベル スタイル（`--text-muted`）で置く
- 入りきらないときは文字を小さくせず、説明に要らない行を `...` で省略する
- 文中のコードは `--font-mono` ＋ 背景 `--bg-subtle` / `radius 4px` / `padding 0 4px`（文字は `--text`、サイズは本文と同じ）

### Tag / Badge

`bg --bg-subtle` / `--text-muted` / `radius 4px` / `padding 2px 8px` / ラベル スタイル。
状態を示すタグのみ semantic soft 背景 ＋ 対応する濃色文字。

### Divider

`1px solid --border`。**2px 以上の区切り線・二重線・破線は使わない。**

### Icon

線画 `1.5px` 単色（`--text` または `--text-muted`）、サイズ 16 / 20 / 24px。
**塗りアイコン・多色アイコン・装飾イラスト・ストックフォトは使わない。**

## 5. Layout Principles（レイアウト）

### スペーシングスケール（4px 基準）

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`
**この 9 段以外の値を使わない。** 「なんとなく 18px」が一貫性を壊す最大の原因。

### スライドの基本寸法

| 項目 | 値 |
|---|---|
| アートボード | 1920 × 1080px（16:9） |
| 余白 | 上 72 / 右 88 / 下 64 / 左 88 |
| ブロック間隔 | 32px |

### ページ構成

上から **タイトル → 概要 → 本体 → 脚注 → フッター** の順に置く。

| 領域 | 置くもの | スタイル |
|---|---|---|
| タイトル | ページタイトル（1 行） | ページタイトル |
| 概要 | このページの主張（1〜2 文） | キーメッセージ（帯にする場合は Callout） |
| 本体 | 根拠（箇条書き・表・図・コード・画面キャプチャ・手順） | 4 章の部品 |
| 脚注 | 出典・期間・注記 | 脚注 |
| フッター | 左に資料名、右にページ番号 | フッター |

- 概要・脚注は無ければ省略してよい。順序は入れ替えない
- 表紙・章扉はこの構成の例外（中央揃え可）

### 余白のリズム

| 関係 | 間隔 |
|---|---|
| ラベルと値 | 4px |
| 段落と段落 | 16px |
| 要素ブロック間 | 32px |
| セクション間 | 64px |

**近いものは近く、遠いものは遠く。** 余白を詰めて要素を増やさない。入らないときは §9 原則 4 に従って削る。

### 揃え

- **左揃えが基本。** 中央揃えは表紙・章扉のみ
- 数値は右揃え、単位は揃える
- 1 ページ ＝ 1 メッセージ。主張が 2 つ入りそうなら、1 つに絞り、もう一方は削る

## 6. Depth & Elevation（奥行き）

**この design system は「面」ではなく「線」で階層を作る。スライドでは影を使わない。**

- 本文・カード・表・コードブロックは影なし。`--bg-subtle` か `1px --border` で区切る
- 角丸は `4px`（小）/ `8px`（カード・コードブロック）の 2 種のみ
- ドロップダウン・モーダルなど「浮いている要素」の影は Web 専用（→ 付録）

---

## 7. Do's and Don'ts（ガードレール）

### Do

- 迷ったら**余白を増やす**。入らないときは**優先度の低い情報から削る**
- 強調は accent を **1 か所**に集中させる
- 図表は 3 色以内。注目させたい 1 系列だけ accent、残りはグレー
- 数値には**出典と期間**を必ず添える
- 状態は色＋語（`⚠ 遅延` のように）で示す。TIPS / 注意の枠にはラベル語を書く
- 同じ意味には同じ語を使う（見出しと目次の文言を一致させる）

### Don't

- ❌ グラデーション・ドロップシャドウ・立体・3D グラフ・多系列の円グラフ
- ❌ 図表で 4 色以上（例外条件を満たす場合を除く）
- ❌ 定義外のフォント・色を作る（コードブロックの 4 色以外のシンタックス色も含む）
- ❌ 装飾用のイラスト・写真・多色アイコン
- ❌ 1 ページに主張を複数詰める
- ❌ 本文を 20px、コードを 18px より小さくして情報を詰め込む
- ❌ TIPS / 注意の枠を 1 ページに 2 つ以上置く、キーメッセージの帯と帯で並べる
- ❌ 色だけで良し悪しを示す（赤＝悪 / 緑＝良）
- ❌ スペーシングスケール外の余白、角丸 4/8px 以外の値
- ❌ 中央揃えの本文、両端揃え、文字間の手動調整

## 8. Output & Delivery（配布・投影）

> **設計根拠**: [ADR-0018](../adr/0018-design-system-slide-first-windows-fonts.md)

配布・投影の基準は **Windows の PowerPoint** とする。

### フォント

- 使う書体は §3 の 2 つだけ。PowerPoint の「英数字用」「日本語用」の両方に同じ書体を指定する（片方だけだと、もう片方が既定の書体に置き換わる）
- 太さは書体名で選ぶ: 400 = `Yu Gothic UI` / 600 = `Yu Gothic UI Semibold` / 700 = `Yu Gothic UI` の太字
- Mac では Yu Gothic UI / BIZ UDゴシック が標準搭載でない場合があり、フォールバックに置き換わる。仕上がりは Windows で確認する

### 単位

この定義は px で書く。PowerPoint は pt で表示するため **`pt = px × 0.75`**（1920×1080px = 1440×810pt）で読み替える。各サイズの pt は §3 のスケール表にある。

### 投影・配布の追加ルール

- 1 ページの根拠は 3 点まで。グラフは 1 ページ 1 つ、系列は 3 つまで
- 凡例より**直接ラベル**。グリッド線は最小限、枠線なし
- 最終ページには担当・期限・依頼事項を必ず置く

## 9. Agent Prompt Guide（Claude Design への指示テンプレート）

このファイルを読み込ませたうえで、次の形で依頼する。

### 新規作成

```
このデザインシステムに従って <作るもの> を作って。
- 目的: <何を決めたい／伝えたいか>
- 対象: <誰が見るか>
- 制約: 図表は chart_palette の 3 色以内、1 ページ 1 メッセージ、
        フォントは Yu Gothic UI / BIZ UDゴシックだけ、本文 20px・コード 18px 以上
```

### スライド（詳細指示は指示書 YAML を併用）

```
このデザインシステムをスライドに適用して。
ページ構成と内容は、添付の指示書 YAML と、deck_type に対応する資料タイプの型に従う。
レイアウト・図の種類・文章表現は、このデザインシステムの範囲で任せる。
デザインの判断はすべてこのデザインシステムを優先する。
```

→ 指示書 YAML の作り方は [docs/design/README.md](./README.md) を参照。

### 修正・レビュー

```
このデザインシステムに照らして、逸脱している箇所を指摘して直して。
特に「7. Do's and Don'ts」の Don't に該当する箇所を優先。
```

### 判断に迷ったときの原則（Claude 向け）

1. 未定義の値や部品が必要になったら、**スペーシングスケール・3 色ルール・タイポスケール・4 章の部品の範囲内**で最も近いものを選ぶ。新しい色・フォントは作らない
2. 装飾を足すか迷ったら**足さない**
3. 色を増やすか迷ったら**グレースケールで階層を作れないか**を先に検討する
4. ページ数の上限があるときは分割せず、**優先度の低い情報から削る**（上限が無くても、まず削れないかを検討する。文字を小さくして収めない）

## 付録: Web / UI への適用

スライド以外（Web ページ・UI モック）で使う値。色・フォント・スペーシング・角丸は本文（2〜6 章）のトークンをそのまま使い、ここでは Web 固有の値だけを定める。

### タイポスケール（Web / ドキュメント）

| 用途 | size | weight | line-height | color |
|---|---|---|---|---|
| H1 | 40px | 700 | 1.2 | `--text` |
| H2 | 30px | 600 | 1.3 | `--text` |

### Button

| variant | 背景 | 文字 | 枠線 |
|---|---|---|---|
| primary | `--accent` | `--text-on-accent` | なし |
| secondary | `--bg` | `--text` | 1px `--border-strong` |
| ghost | 透明 | `--text` | なし |
| danger | `--danger` | `#FFFFFF` | なし |

共通: `height 32px` / `padding 0 12px` / `radius 4px` / `font-size 14px` / `font-weight 500`
状態: `hover` = 背景を 1 段濃く（ghost/secondary は `--bg-hover`、primary は `--accent-hover`） / `active` = さらに 1 段 / `focus-visible` = `outline 2px --accent, offset 2px` / `disabled` = `opacity .5, cursor not-allowed`

### レスポンシブ

| breakpoint | 幅 | 挙動 |
|---|---|---|
| mobile | `< 640px` | 1 カラム。サイドバーはドロワー。左右余白 16px。表は横スクロール |
| tablet | `640–1024px` | 2 カラム。サイドバー折りたたみ。左右余白 48px |
| desktop | `> 1024px` | 12 カラム。サイドバー常時表示。本文最大幅 720px |

- タッチターゲットは **最小 44×44px**（ボタン高さ 32px でも当たり判定を広げる）
- 表は縮小せず `overflow-x: auto` で横スクロール。**文字を小さくして収めない**
- 3 カラムのカードは tablet で 2 列、mobile で 1 列に折り返す
- 画像は `max-width: 100%`。トリミングよりレイアウト変更で対応する
